# Changelog

## 2026-07-27 — Fix cedi sign (`₵`) rendering as tofu boxes on Android
- Root cause: none of the three bundled families (`DMSans`, `DMSerifDisplay`, `JetBrainsMono`) has a glyph for U+20B5, verified by reading each TTF's `cmap` table; Android's system fallback chain doesn't reliably supply it either, so every `GH₵`/`₵` string rendered a box
- Bundled `assets/fonts/InterCurrency[opsz,wght].ttf` — a 24 KB subset of Inter (U+0024, U+00A2–U+00A5, U+20A0–U+20BF) that retains the `wght` axis so the glyph matches surrounding text weight — and declared it as family `InterCurrency` at weights 100–900
- Added `RLTokens.fontFallback` and wired it through `buildTheme()`: `ThemeData(fontFamilyFallback:)`, `textTheme.apply(fontFamilyFallback:)`, plus the three inline styles that bypass the text theme (app-bar title, elevated-button label, input hint). The ~800 widget-level `TextStyle`s that set only `fontFamily` inherit the fallback via `DefaultTextStyle` merge — no per-widget changes needed
- Added `test/shared/font_coverage_test.dart`: parses every bundled TTF's `cmap` and fails if a currency-block rune used anywhere in `lib/` has no glyph in any bundled font; also asserts the theme's styles carry the fallback. Verified it fails without the fix
- Modules affected: `assets/fonts/`, `pubspec.yaml`, `shared/tokens.dart`, `shared/theme.dart`, `test/shared/`

- New API methods on `MaintenanceRequestApi`: `getMaintenanceRequest` (single fetch, populate mirrors the web portal's `server.ts`), `getActivityLogs`, `getComments`, `getExpenses` — the three sub-resources share one `_getRows` helper since all are `{data:{rows,meta}}` under the same request path. `getMaintenanceRequests`' `statusLabel` became optional (the backend reads `status` as a repeatable param and skips the filter when absent)

The board now passes `unit.property_id` via GoRouter `extra`; `maintenanceRequestPropertyId` recovers it from the cross-property list when absent (deep link / cold start), so the route stays a plain `/:id`
- Extracted the board's cancel-reason sheet into `activity/maintenance_status_actions.dart` (`MaintenanceCancelReasonSheet`, `confirmMaintenanceResolve`, `promptMaintenanceCancelReason`, `pickMaintenanceStatus`) — the board and the detail screen must gate Resolved/Cancelled identically, so those prompts now live in one place instead of drifting

Only Priority renders as a tag (`RLPill`, tone-coded): it is the one value carrying a status meaning, so it earns the colour, where wrapping a person's name or a category in a tag would imply a status it doesn't have. `Unassigned` dims to `mutedSoft` since it's a prompt to act rather than a value. Unit and Lease deliberately differ in both colour and glyph — crimson text plus a forward arrow: a chevron edits something on this screen, an arrow leaves it
- **Trailing-glyph alignment**: `_SpecRow` gives all leftover width to a single `Expanded` and right-aligns the trailing group inside it. An earlier revision used `Spacer()` plus `Flexible(trailing)` — both default to `flex: 1`, so Flutter split the leftover space 50/50 and laid the trailing group out at the *left* edge of its half, leaving short values like `Medium` floating mid-row while long ones like `Gideon Bempong` looked nearly correct. Covered by a regression test (below)
- **Unit and Lease navigation is live** — both destinations already existed (`/properties/:id/units/:unitId` and `/more/leases/:id?property_id=`), and the request carries `unit.property_id`, `unit_id` and `lease_id`, so both rows now push for real. Each is rendered only when its property scope is resolvable, so a row is never shown as a link it can't follow
- Status change is live on the detail screen (reuses `MaintenanceRequestStatusNotifier`); Assign, post comment, add expense and the five tokenized field-edits surface a "Coming soon" toast rather than dead-tapping — the rows are already built as tap targets, so wiring each one is a matter of swapping the placeholder for its sheet
- Attachments render as images with a labelled file fallback (bare URLs, no MIME hint) and open externally via `url_launcher`; no `cached_network_image` dependency was added
- Modules affected: `api/maintenance_request_api.dart`, `lib/maintenance_utils.dart` (added visibility mapping), `repository/models/` (3 new + 1 extended), `repository/providers/activity/` (new), `modules/main/activity/` (`maintenance_detail.dart` rewritten, `maintenance_detail_tabs.dart` + `maintenance_status_actions.dart` new, `maintenance_board.dart` rewired), `navigation/routes.dart`
- **Backend Swagger fix (`services/main`)**: `transformations.OutputMaintenanceActivityLog` declared no `performed_by_client_user` field even though `DBMaintenanceActivityLogToRest` has always emitted one — the generated Swagger spec under-reported the activity-log response, so anyone building against the docs (including this screen's History tab) would not have known the performer was available. Added it as `*OutputClientUser` (nullable — `DBClientUserToRest` returns nil for an absent user) and regenerated docs. Also corrected `OutputMaintenanceRequestComment.CreatedByClientUser` from a value `OutputClientUser` with a no-op `omitempty` to `*OutputClientUser`, matching the same transform's nullable output; this changes no Swagger output (swaggo renders struct and pointer-to-struct identically) but makes the Go type honest
- New `test/modules/main/activity/maintenance_detail_test.dart` — the first pm_mobile widget test with real provider overrides (the existing board test only mounts a bare widget). Its fixture deliberately mixes a wide value against a narrow one, since equal-width values hide trailing-glyph misalignment entirely, and it asserts all seven trailing glyphs (5 chevrons + 2 arrows) share one right edge within 0.5px
- **History timeline narrates like the web portal.** Ported `ActivityTab`/`ActivityDetail` from `apps/property-manager/.../request/activity-tab.tsx` so both clients tell the same story. The backend never writes `description` on an activity log, so every sentence is composed client-side from `action` + `metadata` + the request, rendered via `Text.rich` with per-segment emphasis (values and names in ink-semibold, "(assigned to themselves)" italic) and an inline avatar for the person named. Branches: CREATED distinguishes manager-filed / filed-on-behalf-of-tenant / tenant-submitted; STATUS_CHANGED reads `metadata.from`/`to` and maps the raw enums through `mrStatusLabel`; assignments read the assignee **off the request**, not the log

Now send `PerformedByClientUser,PerformedByClientUser.User,PerformedByTenant` and `CreatedByClientUser,CreatedByClientUser.User` respectively, matching the web portal exactly. Third instance of this class of bug in the repo, after the `getMyProperties` `populate=Property` fix logged on 2026-07-25 — it fails silently rather than erroring, which is why it keeps recurring
- New `test/api/maintenance_request_api_test.dart` pins the populate list of all four detail reads. It overrides `AbstractApi.execute` (the single choke point every call goes through) to capture the request path, so no HTTP mocking or production seam is needed. Expenses deliberately assert *no* populate: the web populates `Invoices` there, but the mobile tab shows only amount/description/date
- `MaintenanceRequestModel` gained `created_by_tenant_id`, `created_by_client_user_id` and a minimal `MaintenanceTenantModel` (`created_by_tenant`) — the fields the CREATED branch needs to tell "created by a manager" from "submitted by a tenant"
- **Bug fix — `RLBtn` labels overflowed instead of ellipsizing.** The label `Text` sat unconstrained in a `mainAxisSize.max` Row, so any full-width button whose label outgrew its box threw a RenderFlex overflow rather than truncating. Surfaced by the detail screen's two-button action bar at 400pt (it would break on a 375pt iPhone SE); wrapped in `Flexible` with `maxLines: 1` + ellipsis. Shared primitive, so this fixes every long-labelled button in the app
- History-tab widget tests cover all four sentence branches. They also pin the test surface to 400×3000: the screen is a lazy `ListView`, and at the default 600pt height the timeline is never built, so assertions about it silently pass by matching identical text in the Assignments card above
